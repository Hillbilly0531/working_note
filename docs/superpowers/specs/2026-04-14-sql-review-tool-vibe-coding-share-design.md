# SQL Review Tool Vibe Coding 分享页设计

## 概述

基于文档《SQL Review Tool 项目经验分享：Vibe Coding 内部复盘》，制作一个类似 PPT 的单文件 HTML 分享页，用于跨团队场景下的内部演讲与留档传播。

本次交付不是普通文章页，而是一个可全屏演示、支持键盘翻页、具备科技展示感的网页演示稿。

## 目标

- 将原始 Markdown 复盘内容浓缩为 8-10 页的演示稿
- 采用全屏翻页式 HTML 呈现，体验接近正式 PPT
- 风格偏科技展示型，强化舞台感、节奏感与可传播性
- 面向跨团队听众，兼顾技术含量与可理解性
- 最终产物为一个本地可直接打开的单文件 HTML

## 非目标

- 不做成普通长文滚动页
- 不追求逐字保留原始 Markdown 全量内容
- 不依赖外部 CDN、前端框架或构建流程
- 不增加演讲备注、后台管理、在线协作等额外功能
- 不做复杂的逐条点击演示逻辑

## 成功标准

- 页面可本地双击打开并正常展示
- 支持键盘翻页与全屏演示
- 总页数控制在 9 页左右
- 每页信息密度适合演讲，不出现大段难以阅读的正文堆积
- 视觉风格统一，明显区别于普通办公模板
- 核心观点清晰传达：
  - 不是让 AI 代替开发
  - 而是让 AI 在清晰边界、明确计划和持续验证中成为高响应协作者

## 受众与使用场景

### 目标受众

- 技术为主的跨团队分享场景
- 听众包含开发、测试、产品、项目协作角色

### 使用方式

- 现场投屏分享
- 本地打开演示
- 作为 HTML 文件在团队内部流转

## 内容策略

原始文档信息量较大，HTML 演示稿采用“演讲型浓缩”策略：

- 每页只表达 1 个主判断
- 每页正文控制在短句、关键词、卡片说明内
- 优先保留方法论、协作经验、可复用案例
- 压缩重复论证、过细实现细节和展开解释
- 保留结尾金句作为收束页核心文案

## 信息架构

### 页数

- 目标页数：9 页

### 分镜

1. 封面页
2. 项目背景页
3. 协作原则页
4. 高效沟通四动作页
5. 高价值 Skills 页
6. 模式配合页
7. 工作流页
8. 典型案例页
9. 收尾总结页

## 单页设计说明

### 1. 封面页

用途：建立主题、风格和主论点。

内容：

- 标题：SQL Review Tool
- 副标题：Vibe Coding 内部复盘
- 一句定位文案：不是让 AI 代替开发，而是把 AI 变成高响应、低摩擦的协作搭子。

视觉：

- 深色科技背景
- 网格与发光节点
- 左文右图或中心聚焦布局

### 2. 项目背景页

用途：解释为什么这个项目适合用来讲 Vibe Coding。

内容：

- 项目面向内部 SQL 审查场景
- 能力涉及规则检查、Explain、元数据辅助、AI 建议
- 工程范围跨前端、后端、配置、打包、测试、文档
- 复杂度足够高，但边界可以被定义

视觉：

- 4 张核心信息卡片
- 大标题 + 简洁说明

### 3. 协作原则页

用途：突出核心方法论。

内容主轴：

- 先讲目标，再讲边界
- 用四段结构表达需求：
  - 业务目标
  - 范围边界
  - 禁止改动
  - 验收标准

视觉：

- 中轴式结构带
- 关键词放大

### 4. 高效沟通四动作页

用途：总结最实用的沟通框架。

内容：

- 讲目标
- 讲非目标
- 分块推进
- 验证后再宣布完成

视觉：

- 2x2 象限卡片
- 每块一条解释

### 5. 高价值 Skills 页

用途：总结最有价值的协作技能，不追求枚举完整。

内容：

- brainstorming：先把问题说完整
- writing-plans：把设计收成可执行计划
- verification-before-completion：避免“以为完成”
- systematic-debugging：让排障从补丁式改为分层定位

视觉：

- 纵向高亮卡片
- 强调“skill 解决了什么失控风险”

### 6. 模式配合页

用途：说明不同模式在不同阶段的职责。

内容：

- Plan Mode：澄清问题
- Agent Mode：执行落地
- Debug Mode：定位异常

结论：

- 先澄清，再落地，出错后定位，再回到实现

视觉：

- 三列对比
- 底部放一条总括结论

### 7. 工作流页

用途：沉淀可复用的 Vibe Coding 流程。

主流程：

- 设计
- 计划
- 实现
- 验证
- 修复
- 再验证

视觉：

- 横向主流程图
- 连接线与节点高亮
- 这一页应是全稿视觉最强页面之一

### 8. 典型案例页

用途：用实例让方法论落地。

案例：

- 功能语义纠偏
- 把实现边界写进要求
- 打包时明确保留什么、排除什么

视觉：

- 三张并列大卡片
- 具备“错误理解 vs 正确表达”的对照感

### 9. 收尾总结页

用途：收束全稿并留下可传播结论。

内容：

- 3 条经验短句
- 1 条金句总结

视觉：

- 更安静、更聚焦
- 适合演讲结束停留与截图传播

## 视觉设计

### 风格

- 深色发布会风
- 数据流与系统感
- 科技展示型而非办公模板型

### 色彩

- 背景主色：`#07111f`
- 信息高亮：`#7dd3fc`
- 正向结论：`#22c55e`
- 风险提醒：`#f59e0b`
- 正文文字：`#e5f0ff`

### 元素语言

- 网格背景
- 渐变光斑
- 细线连接
- 大数字、大标题、大留白

### 视觉原则

- 避免信息过载
- 避免模板感
- 避免夸张廉价动画
- 保持每页都具有明显的视觉重心

## 交互设计

### 翻页方式

- 左右方向键翻页
- 上下方向键翻页
- 空格键下一页
- Home 跳转首页
- End 跳转末页

### 演示辅助

- 右下角显示当前页码与总页数
- 左下角显示当前章节标签
- 页面支持全屏演示

### 动效原则

- 页面切换采用轻微位移与淡入
- 单页内部元素分层入场
- 不做复杂点击触发的逐条揭示
- 动效服务于节奏，不抢内容

## 技术方案

### 交付形式

- 单文件 HTML
- 内联 CSS
- 内联 JavaScript

### 技术约束

- 不依赖外部网络资源
- 可在本地浏览器直接打开
- 代码结构清晰，便于后续手动改字

### 页面结构建议

- 使用语义化 section 表示每一页
- 使用固定 viewport 布局实现全屏幻灯片
- 使用简单状态机控制当前页索引和翻页动画

## 文案改写原则

- 忠于原文核心结论
- 优先保留强判断句
- 将长段落改写为演讲友好型表达
- 面向跨团队听众时减少术语堆叠

## 风险与控制

### 风险

- 科技风过强导致内容可读性下降
- 原文信息量过大导致页面塞字
- 视觉动效过多造成“像网页，不像演示稿”

### 控制手段

- 严格限制每页文本量
- 用卡片、流程、关键词替代长文
- 保持转场克制，优先阅读节奏

## 验证方案

- 在本地浏览器直接打开 HTML 验证展示效果
- 逐页检查翻页逻辑、页码、章节标签是否正确
- 检查窗口尺寸变化时的布局稳定性
- 检查 16:9 常见演示屏幕下的可读性
- 检查全文是否仍准确表达原始复盘主线
