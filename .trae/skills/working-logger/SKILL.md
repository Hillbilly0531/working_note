# 工作日志记录器

## 核心规则

**触发条件（按优先级）：**

1. **最高优先级**：检测到 `<system-reminder>` 中包含 `working-note.md` 或 `working-logger` 关键词
2. **必须调用**：用户开始任何新对话时
3. **必须调用**：用户开始新聊天或继续现有对话时
4. **必须调用**：收到包含 `working_note` 规则的 system-reminder 时

**调用位置**：收到用户消息后，**立即作为第一个工具调用**，不要有任何迟疑或延迟。

## 简化操作流程

### 1. 对话开始时（检测到触发条件）

**立即执行：**
1. 调用 `<invoke name="Skill"><parameter name="name">working-logger</parameter></invoke>`
2. 确定当前工作目录（项目根目录）
3. 读取今天的日志文件（如果存在）
4. 检查是否有未记录的内容需要补充

**确定项目根目录的方法**：
- 优先使用环境变量或系统信息中的当前工作目录
- 如果无法确定，则使用 `d:\IdeaProjects\working_note` 作为默认项目目录
- 日志文件路径格式：`{项目根目录}/.working_logger/{YYYY-MM-DD}.md`

### 2. 对话进行中

记录以下内容（通过 todo list 跟踪）：
- 当前讨论的主题
- 已完成的任务
- 正在进行的任务
- 代码变更的文件路径

### 3. 对话结束时（或用户表示完成时）

**必须执行：**
1. 更新工作日志文件
2. 合并到现有文件中
3. 确认保存成功

## 日志文件位置

每个项目的工作日志存储在该项目根目录的 `.working_logger` 目录下：

```
{项目根目录}/.working_logger/{YYYY-MM-DD}.md
```

**注意**：
- `.working_logger` 目录默认不提交到 git
- 如果项目使用 git，应将此目录添加到 `.gitignore` 文件中
- 日志按日期分文件存储，每天一个文件

## 日志文件格式

```markdown
# 工作日志 - {YYYY-MM-DD}

## 对话记录

### {HH:MM} - {主题}

**内容摘要**：
- {讨论摘要}

**完成任务**：
- [x] {任务 1}
- [x] {任务 2}

**进行中任务**：
- [ ] {进行中任务}

**代码变更**：
- {文件更改}

**备注**：
{其他备注}

---
```

## 错误处理

1. **目录不存在**：创建 `.working_logger` 目录，如果创建失败则使用备用位置
2. **文件不存在**：创建新文件，使用标准格式
3. **文件已存在**：读取现有内容，追加新记录
4. **写入失败**：记录到控制台输出，提示用户手动记录

## 关键提醒

- **语言**：日志内容始终使用中文
- **时间**：保持当天日志的时间顺序
- **简洁**：摘要要简洁但全面
- **路径**：包含任何代码修改的文件路径

## 检测规则

在以下情况下必须调用此 skill：

1. ✅ `<system-reminder>` 中有 `working-note.md`
2. ✅ `<system-reminder>` 中有 `working-logger`
3. ✅ `<system-reminder>` 中有 `rules` 且包含 `working_note`
4. ✅ 用户发送第一条消息
5. ✅ 用户开始新对话
