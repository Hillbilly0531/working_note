# Flink MySQL CDC → Elasticsearch 数据同步问题总结（完整复盘）

&#x20;

## 一、整体现象

Flink 任务启动正常、MySQL CDC 能读到数据，但 **Elasticsearch 始终无数据**，并伴随多种报错、任务异常退出。

***

# 二、所有遇到的坑 + 根本原因 + 解决方案

## 坑 1：Flink SQL 无法查询 ES 表（CannotPlanException）

**原因**：Elasticsearch 连接器只支持 **Sink（写入）**，不支持流模式 **Source（查询）**，不能用 `SELECT * FROM es_table`。

**解决方案**：只使用 `INSERT INTO` 写入，不查询 ES 表。

***

## 坑 2：ES 连接配置错误、无法连通

**原因**：hosts 写错、无权限、端口不通。

**验证方法**：

bash

运行

```
curl -u elastic:leyo@@2021 http://192.168.27.55:19200

```

**解决方案**：确保 `hosts = "http://IP:PORT"`、账号密码正确、网络互通。

***

## 坑 3：未开启 Checkpoint → ES 数据不刷新、一直缓存

**原因**：Flink ES Sink 默认 **Checkpoint 触发提交**，不开 Checkpoint 数据永远不落地 ES。

**解决方案**：必须开启：

sql

```
SET execution.checkpointing.interval = 30s;

```

***

## 坑 4：failure-handler = ignore → 错误被静默吃掉

**原因**：写入 ES 失败但不报错、不打印日志。

**解决方案**：测试环境必须设为：

sql

```
'failure-handler' = 'fail'

```

***

## 坑 5：日期格式不兼容（strict\_date\_optional\_time）

**原因**：ES 不识别 `2026-03-31 12:00:00`，只认 ISO 格式或时间戳。

**解决方案**：使用 **毫秒时间戳 BIGINT** 最稳妥。

***

## 坑 6：datagen 生成无限大 DOUBLE → ES float 溢出报错

**原因**：datagen 默认生成超大浮点数（Infinity），ES float 无法存储。

**解决方案**：必须限制范围：

sql

```
'fields.sale_amount.min' = '0.01'
'fields.sale_amount.max' = '1000.0'

```

***

## 坑 7：UNIX\_TIMESTAMP 不支持 TIMESTAMP (3) 类型

**原因**：Flink SQL 中 `UNIX_TIMESTAMP` 只支持字符串，不支持时间类型。

**正确写法**：

sql

```
CAST(TIMESTAMPDIFF(SECOND, TIMESTAMP '1970-01-01 00:00:00', ts) * 1000 AS BIGINT)

```

***

## 坑 8：任务运行一会儿自动退出

**原因**：SQL Client 按了 Ctrl+C、关闭窗口、会话断开。

**解决方案**：提交前开启后台运行：

sql

```
SET execution.detached = true;

```

***

# 三、最终可用的正确配置（核心结论）

## 1. 必须开启 Checkpoint（最关键）

sql

```
SET execution.checkpointing.interval = 30s;

```

## 2. ES Sink 正确配置

sql

```
'connector' = 'elasticsearch-7',
'hosts' = 'http://192.168.27.55:19200',
'username' = 'elastic',
'password' = 'leyo@@2021',
'index' = 'ts_saleoutmt',
'failure-handler' = 'fail',
'format' = 'json'

```

## 3. 时间字段必须用 BIGINT 毫秒戳

sql

```
ts BIGINT

```

## 4. 数值字段必须限制范围（避免 Infinity）

sql

```
'fields.sale_amount.min' = '0.01',
'fields.sale_amount.max' = '1000.0'

```
