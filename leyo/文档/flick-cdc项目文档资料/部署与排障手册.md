# 部署与排障手册

> 面向运维和联调同学，按步骤执行即可。
> 更新日期：2026-04-17

## 1. 部署前准备

### 1.1 环境基线

- JDK 8
- Maven 3.8+
- 可访问 Nacos、MySQL、Elasticsearch
- MySQL 已开启 binlog 且 `binlog_format=ROW`

### 1.2 配置准备

1. 确认 `bootstrap.yml` 中目标环境 `profile`、`namespace`、`group`
2. 在 Nacos 准备好数据源、redis、业务依赖配置
3. 检查 Job YAML 是否启用（`enabled`）
4. 对敏感配置使用密文或环境变量，不在仓库明文保存

## 2. 启动与验证

### 2.1 打包

```bash
mvn clean package
```

### 2.2 启动

```bash
java -jar target/solar-openapi.jar
```

### 2.3 健康检查

```text
http://127.0.0.1:24051/actuator/health
```

### 2.4 CDC 任务检查

日志里重点看这些关键字：
- `[CDC_BOOT] Submit job`
- `CDC Runner MySQL Source 创建完成`
- `开始启动 CDC Job`
- `CDC Job 批量写入 ES 完成`

## 3. 上线检查清单

- Nacos 配置是否加载成功
- MySQL 源库和回查库是否连通
- ES 地址和认证是否有效
- Job 对应 SQL、Mapping 文件是否存在
- `startupMode` 是否符合上线预期
- 是否明确接受当前 `DELETE` 不处理策略

## 4. 常见问题与处理

### 4.1 任务启动了，但没有数据

先查：
1. `listenOps` 是否包含当前操作类型
2. SQL 回查是否能按主键查到数据
3. 回查结果字段里是否有 `documentIdField` 指定字段
4. ES 索引名是否写错

### 4.2 ES bulk 有失败项

现象：日志有 `ES bulk 存在失败项`

处理顺序：
1. 看失败的 `_id` 和原因
2. 对照 mapping 检查字段类型
3. 检查索引模板是否覆盖了旧结构
4. 必要时先建新索引做灰度

### 4.3 MySQL 连接异常

排查：
- 数据源 URL 是否可达
- 用户权限是否具备 CDC/查询能力
- `jdbc:p6spy:` 前缀在 CDC 源连接中是否被正确规范化

### 4.4 应用启动即失败（配置相关）

排查：
- Nacos 地址、命名空间、group
- profile 是否选错
- 配置文件编码是否一致（推荐 UTF-8）

### 4.5 启动卡住或启动特别慢

从当前版本开始，`CdcJobRunner` 内置了启动阶段诊断。

重点日志关键词：
- `CDC Runner 启动阶段超时`
- `CDC Runner 线程栈`

阶段名含义：
- `build_mysql_source`：构建 MySQL CDC Source
- `create_flink_source_stream`：创建 Flink Source 流
- `wire_flink_pipeline`：拼接 flatMap + sink 管道
- `execute_flink_job`：提交执行 Flink Job

实战建议：
1. 先看卡在哪个阶段
2. 再看同一时间的线程栈（mysql / debezium / flink 相关线程）
3. 最后回到网络、权限、版本兼容性逐项核对

## 5. 回滚建议

- 如果是 Job 级问题：先把对应 Job 改为 `enabled: false`，重启后快速止损
- 如果是依赖升级问题：按最近一次依赖变更回滚，恢复已验证版本组合
- 回滚后优先跑最小冒烟：启动、健康检查、单 Job 数据写入

## 6. 联调建议

- 先用测试索引验证，不要直接打生产索引
- 单 Job 通过后再并行开启多个 Job
- 建议给每个 Job 配独立日志检索关键字，方便值班定位
