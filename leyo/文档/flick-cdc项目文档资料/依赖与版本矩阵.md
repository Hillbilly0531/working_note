# 依赖与版本矩阵

> 这份文档专门解决一个问题：为什么依赖总在改，以及怎么改才不炸。
> 更新日期：2026-04-17

## 1. 先记住这条原则

这个项目是“Spring Boot + Flink CDC + 自定义 Sink”的混合体。
依赖不能按单框架思路随便升，需要按组合关系看。

一句话原则：
- 先锁 Flink 主版本
- 再锁 Flink CDC 版本
- 再校验 MySQL 驱动、连接池、日志体系是否兼容

## 3. 依赖分层（按职责看）

### 3.1 Flink/CDC 主链路

- `org.apache.flink:flink-clients:${flink.version}`
- `org.apache.flink:flink-core:${flink.version}`
- `org.apache.flink:flink-streaming-java:${flink.version}`
- `org.apache.flink:flink-connector-base:${flink.version}`
- `org.apache.flink:flink-table-common:${flink.version}`
- `org.apache.flink:flink-connector-mysql-cdc:${flink.cdc.version}`

这层是 CDC 能不能跑起来的核心，建议不要局部升某一个 Flink 包。

### 3.2 数据库与连接池

- `com.mysql:mysql-connector-j:${mysql.driver.version}`
- `com.zaxxer:HikariCP:${hikari.version}`
- `spring-boot-starter-jdbc`
- `dynamic-datasource-spring-boot-starter`
- `p6spy:p6spy`

特别注意：
- CDC 依赖里排除了 `mysql:mysql-connector-java`
- 项目自己引入了 `com.mysql:mysql-connector-j`

这样做是为了避免旧驱动坐标和新驱动坐标混用导致类冲突。

### 3.3 Spring 与基础能力

- `spring-boot-autoconfigure`
- `spring-boot-starter-aop`
- `spring-boot-starter-validation`
- `spring-cloud-starter-alibaba-nacos-config`
- `spring-cloud-starter-alibaba-nacos-discovery`
- 企业内部 starter（web / mybatis-plus / log-core）

这层大多由 parent 或企业 starter 间接管理，改动前要先看传递依赖。

### 3.4 日志与监控

- `spring-boot-starter-log4j2`
- `leyo-server-log-core`
- Actuator 能力来自企业 starter 组合（管理端口见 `application.yml`）

## 4. 最常见的冲突点（也是最容易来回改的地方）

1. Flink 与 CDC 版本错配
- 现象：启动时报类找不到、方法签名不匹配
- 处理：Flink 相关依赖统一跟 `flink.version`，CDC 单点升降前先验证官方兼容矩阵

2. MySQL 驱动坐标混用
- 现象：JDBC 驱动加载异常、ClassNotFound
- 处理：坚持单一坐标 `com.mysql:mysql-connector-j`，避免和 `mysql:mysql-connector-java` 共存

3. Hikari 版本被传递依赖覆盖
- 现象：连接池参数不生效或运行时告警
- 处理：保持显式版本并观察 `mvn dependency:tree` 最终解析结果

4. 日志实现冲突（logback/log4j2）
- 现象：启动时出现 multiple bindings 警告
- 处理：统一走 log4j2 方案，检查是否有第三方包把 logback 带回来

5. 企业 starter 与开源依赖版本打架
- 现象：某些 Spring 组件行为异常但编译正常
- 处理：改版本前先看 parent 和 starter 的约束，尽量在受控范围内调整

## 5. 依赖变更的推荐流程（务实版）

1. 先说明目标（修 bug、补功能、安扫整改）
2. 只改最小范围依赖，不做顺手大升级
3. 执行依赖树检查（至少看 Flink、MySQL、日志）
4. 跑基础验证：编译、启动、一个 CDC Job 冒烟
5. 记录变更原因和回滚方式

推荐命令：

```bash
mvn -DskipTests dependency:tree
mvn -DskipTests dependency:tree -Dincludes=org.apache.flink
mvn -DskipTests dependency:tree -Dincludes=mysql
mvn clean test
mvn clean package
```

## 6. 升级策略建议

- 小步升级：一次只动一类依赖
- 必做回归：CDC 启动、主键路由、SQL 回查、ES bulk 写入
- 先在测试环境开启 `enabled=true` 做实流量验证，再推生产

## 7. 结论

当前这套版本组合已经能跑通项目场景。后续如果要升级，优先按“链路兼容性”而不是“单包最新版本”来决策。
