# 需求拆解心法与通用提示词

## 一、拆解心法（哲学层）

核心原则：先切决策点，再切交付闭环，最后切验证边界。

- 决策点优先：优先识别 if/else、规则分支、角色差异、状态流转。
- 闭环最小化：每个任务都应可独立开发、评审、测试、回滚。
- 验证先行：拆解时就定义“如何证明完成”。
- 风险前置：先低耦合高确定性，后高复杂高风险。
- 兼容兜底：历史数据、默认值、空值、降级逻辑独立成任务。
- 可追踪性：每个任务都要有唯一输入、唯一产出、唯一验收标准。

## 二、通用拆解步骤（方法层）

1. 抽实体：对象、字段、枚举、状态、接口。
2. 抽决策：业务分支、适用矩阵、例外规则。
3. 抽约束：校验、互斥、默认值、兼容策略。
4. 抽公式/算法：计算逻辑、边界、舍入、优先级。
5. 抽流程：时序、前后置依赖、读写路径。
6. 映射任务：按“一个行为变化 = 一个任务”进行切片。

## 三、万能拆解提示词（完整版）

```text
你是资深架构师兼交付教练。请基于我提供的项目文档，输出“可执行的小任务拆解方案”，用于开发-review-测试循环。

【拆解目标】
- 不一次性实现全部需求
- 采用小步快跑，每个任务可独立开发、评审、测试、回滚
- 优先降低风险与耦合，保证持续可交付

【拆解原则】
1) 每个任务只包含一个核心行为变化（一个决策点或一个规则分支）
2) 每个任务都有明确输入、输出、影响范围、验收标准
3) 每个任务必须可独立测试（至少：正向/边界/回归）
4) 兼容性（历史数据、默认值、空值）必须单独成任务
5) 先做基础能力与低风险任务，再做复杂公式与高风险任务
6) 标注任务依赖关系与可并行关系

【请按以下结构输出】
A. 文档关键要素提取：
- 实体/字段
- 枚举/状态
- 业务决策点
- 约束与校验
- 公式与算法
- 兼容策略

B. 任务分层拆解（按阶段）：
- 阶段名（目标）
- 任务列表（T1, T2...）

C. 每个任务卡片模板（逐条输出）：
- 任务ID：
- 任务名称：
- 目标行为（只写一个变化点）：
- 范围（涉及模块/接口/字段）：
- 前置依赖：
- 实现要点（3-5条）：
- Review检查点（3-5条）：
- 测试用例（正向/边界/回归）：
- 完成定义 DoD：
- 风险与回滚方案：

D. 执行建议：
- 推荐迭代顺序（为什么）
- 哪些任务可并行
- 每轮迭代建议时长（如 0.5 天/1 天）

【输出要求】
- 任务颗粒度要小，避免“大而全”
- 优先输出可直接开工的任务
- 避免空泛描述，尽量具体到字段/规则/公式
```

## 四、极速版提示词（30 秒）

```text
请把这份需求文档拆成可执行小任务，要求：
1) 一个任务只改一个决策点
2) 每个任务可独立开发-review-测试-回滚
3) 每个任务都给出：目标、范围、依赖、验收、测试（正向/边界/回归）
4) 历史兼容与默认值单独拆任务
5) 按低风险到高风险排序，并标注可并行任务
请输出“阶段 + 任务卡片”格式。
```

## 五、一句话心法

先把不确定性拆散，再把确定性交付。
