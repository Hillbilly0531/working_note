## 一、功能模块划分及详细任务描述

### 模块A：计提备案核心模块
**功能范围**：备案单全生命周期管理（外部引入、内部分配、年度预算三种备案类型）

| 任务编号 | 任务名称 | 详细描述 | 工作量(天) |
|---------|---------|---------|-----------|
| A1 | 数据库设计与实体建模 | 设计备案主表(fund_pool_record)、资金来源明细表(fund_pool_source_detail)、使用计划表(fund_pool_usage_plan)、操作记录表(fund_pool_operation_log)；含索引设计、外键约束 | 1.5 |
| A2 | 备案单号生成器 | 实现BA+YYMMDD+6位顺序码的生成逻辑，支持并发安全（Redis分布式锁或数据库序列） | 0.5 |
| A3 | 备案CRUD基础接口 | 新增、编辑、删除、查询、保存草稿、状态流转（草稿↔待审核↔审核驳回↔已备案） | 1.5 |
| A4 | 资金来源明细管理 | 明细增删改查、发票/流水附件解析、主凭证id关联、凭证使用状态同步；含"资源归属部门&项目"唯一性校验 | 1.5 |
| A5 | 使用计划管理 | 使用计划增删改查、金额校验（总计划金额=备案金额）、资源归属部门+项目唯一性 | 0.5 |
| A6 | 备案金额计算引擎 | 含税/不含税金额自动计算（票折÷1.15、广告÷1.10、推广÷1.08）、汇总统计 | 0.5 |
| A7 | 备案导入功能 | 外部引入(3sheet)/内部分配(2sheet)/年度预算(2sheet)三种导入模板解析、多sheet级联校验、失败明细Excel导出 | 1.5 |
| A8 | 备案作废功能 | 作废申请（分备案类型显示不同UI数据）、剩余金额计算、作废原因记录、状态流转（备案作废待审核→已作废） | 0.5 |
| A9 | 备案调配功能 | 调配申请、使用计划调整（调出/调入）、金额平衡校验（总调出=总调入）、状态流转 | 0.5 |
| A10 | 备案同步导出 | 按类型生成多sheet Excel导出文件、文件名编码规则（YYYYMMDD+四位顺序码） | 0.5 |
| A11 | 备案分页查询接口 | 多条件筛选（状态、冻结状态、备案人、厂牌池、运营池、时间范围等）、数据权限控制（本人+下属/财务全量） | 1.0 |

**模块A小计：10.5天**

### 模块B：返利凭证集成与冻结同步模块
**功能范围**：与返利凭证系统交互、冻结/解冻/核销记录同步

| 任务编号 | 任务名称 | 详细描述 | 工作量(天) |
|---------|---------|---------|-----------|
| B1 | 冻结记录同步接口 | 备案提交时触发（收款公司≠集团时）、主凭证id查找、可认领金额≥备案金额判断、认领记录生成、冻结状态回写 | 1.0 |
| B2 | 取消冻结同步接口 | 备案作废通过时触发、按备案金额恢复认领资金、认领作废记录生成（金额为负）、取消冻结状态回写 | 0.5 |
| B3 | 核销记录同步接口 | 核销通过时触发、未核销凭证金额随机分配、核销记录生成（集团协议编号=集团营销资源） | 0.5 |
| B4 | 返利凭证字段扩展 | 资金类型枚举扩展（代收代付、非返利-集团营销资源、非返利-子公司推广费、非返利-其他）、新增"预收情况"字段 | 0.5 |
| B5 | 定时任务-凭证状态查询 | 定时查询主凭证id对应发票/银行凭证状态、更新备案明细中凭证使用状态（待认领/部分认领/全部认领） | 0.5 |

**模块B小计：3.0天**

**功能范围**：使用单全生命周期管理、自动调配逻辑

|---------|---------|---------|-----------|

| C4 | 可使用金额查询接口 | 按"备案类型+资源归属部门+厂牌池/运营池+项目"维度查询剩余可使用金额；公式：已备案&&{已冻结||无需冻结} - 作废申请中 - 调配申请中 - 已使用 - 使用申请中 | 1.0 |

| C7 | 使用分页查询接口 | 多条件筛选（状态、特殊状态、核销情况、使用人、厂牌池、时间范围等）、数据权限控制 | 0.5 |

## 四、模块间接口定义及联调计划

### 4.1 核心接口契约定义

#### 4.1.1 备案模块 → 使用模块

```
接口：GET /api/fund-pool/record/available-amount
描述：查询剩余可使用金额
入参：
  - recordType: String (外部引入/内部分配/年度预算)
  - department: String (资源归属部门)
  - brandPool: String (厂牌池，年度预算为空)
  - operationPool: String (运营池，仅年度预算使用)
  - project: String (项目)
出参：
  - availableAmount: BigDecimal (剩余可使用金额，不含税)
  - inUseAmount: BigDecimal (使用审核中金额)
  - usedAmount: BigDecimal (已使用金额)
```

#### 4.1.2 使用模块 → 核销模块

```
接口：GET /api/fund-pool/usage/available-writeoff-amount
描述：查询使用单剩余可核销金额
入参：
  - usageNo: String (使用单号)
出参：
  - List<WriteoffAmountDetail>
    - project: String (项目)
    - resourcePaymentMethod: String (资源兑付方式)
    - availableWriteoffAmount: BigDecimal (剩余可核销金额)
    - inWriteoffAmount: BigDecimal (核销审核中金额)
    - writtenOffAmount: BigDecimal (已核销金额)
```

#### 4.1.3 凭证集成接口

```
Service：FundPoolFreezeService
方法：
  - FreezeResult freeze(String mainVoucherId, BigDecimal amount, String recordNo)
    描述：备案提交时触发冻结
  - FreezeResult unfreeze(String mainVoucherId, BigDecimal amount, String recordNo)
    描述：备案作废通过时取消冻结
  - WriteoffResult writeoff(String mainVoucherId, BigDecimal amount, String usageNo)
    描述：核销通过时触发核销记录
```

#### 4.1.4 审批服务接口

```
Service：ApprovalService
方法：
  - void submit(String bizType, String bizId, String operator, ApprovalParams params)
    描述：提交审批（备案/使用/核销/作废/调配）
  - void approve(String bizType, String bizId, String approver, String remark)
    描述：审核通过
  - void reject(String bizType, String bizId, String approver, String remark)
    描述：审核驳回
```

#### 4.1.5 待办服务接口

```
Service：TodoService
方法：
  - void create(TodoType type, String userId, String bizId, String bizType)
    描述：创建待办消息
  - void resolve(String userId, String bizType)
    描述：标记待办已处理（用于跳转后清空）
  - int count(String userId, TodoQuery query)
    描述：统计待办数量
```

## 七、风险与依赖说明

### 7.1 模块独立性保障

| 措施 | 说明 |
|------|------|
| 接口先行 | W1-D1完成所有跨模块接口契约定义，双方按契约并行开发 |
| Mock服务 | 前期使用Mock数据替代依赖模块返回，解除开发阻塞 |
| DAO层共享 | 汇总模块直接调用DAO方法而非HTTP接口，减少网络依赖 |
| 独立数据库表 | 各模块表结构独立，避免DDL变更相互影响 |

### 7.2 依赖外部系统
