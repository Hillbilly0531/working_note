# 观远接口联调说明：两步调用

本文档用于说明如何在 `https://bi.leyopharm.com` 上完成以下两步调用：

1. 通过 `loginId` 登录，换取访问 Token
2. 将第一步返回的访问 Token 作为 `X-Auth-Token`，调用“获取数据集数据”接口

适用场景：

- 为 `guandata-api-skill` 梳理最小可落地的接口链路
- 先打通观远开放平台鉴权，再逐步补充后续报表或卡片查询接口

参考文档：

- 登录接口：`https://api.guandata.com/apidoc/docs-site/345092/730/api-3471182`
- 数据集数据接口：`https://api.guandata.com/apidoc/docs-site/345092/730/api-3470616`

## 1. 基础信息

- 业务域名：`https://bi.leyopharm.com`
- 文档域名：`https://api.guandata.com`
- 当前已验证：`https://bi.leyopharm.com` 可正常访问，且 `/public-api/...` 路径可命中真实观远服务

注意：

- 文档站点 `api.guandata.com` 只用于看接口说明，不是实际业务调用 Host
- 实际接口调用应走企业自己的观远域名，即 `https://bi.leyopharm.com`

## 2. 第一步：通过 loginId 登录，获取访问 Token

### 2.1 接口说明

- 方法：`POST`
- 路径：`/public-api/user/loginId/sign-in`
- 完整地址：`https://bi.leyopharm.com/public-api/user/loginId/sign-in`

### 2.2 请求参数

请求体为 JSON：

```json
{
  "token": "<应用Token>",
  "loginId": "<用户loginId>"
}
```

字段说明：

- `token`：观远应用级 Token，不是用户访问 Token
- `loginId`：需要登录的用户标识，例如 `LY010583`

### 2.3 curl 示例

```bash
curl --location 'https://bi.leyopharm.com/public-api/user/loginId/sign-in' \
  --header 'Content-Type: application/json' \
  --data '{
    "token": "<应用Token>",
    "loginId": "<用户loginId>"
  }'
```

### 2.4 成功响应示例

成功时会返回可用于后续接口调用的访问 Token：

```json
{
  "result": "ok",
  "response": {
    "token": "<访问Token>",
    "expireAt": "2026-04-13 18:00:00.000"
  }
}
```

### 2.5 失败响应示例

当前已在 `https://bi.leyopharm.com` 上验证过，如果参数不匹配，会返回类似错误：

```json
{
  "result": "fail",
  "response": null,
  "error": {
    "status": 1004,
    "message": "登录失败！账号或密码不正确！",
    "detail": {
      "notifyType": 0
    }
  }
}
```

说明：

- 这表示接口链路是通的
- 当前阻塞点是 `token` 或 `loginId` 不正确

## 3. 第二步：使用第一步返回的访问 Token，获取数据集数据

### 3.1 接口说明

- 方法：`POST`
- 路径：`/public-api/data-source/{dsId}/data`
- 完整地址：`https://bi.leyopharm.com/public-api/data-source/{dsId}/data`

### 3.2 请求头

必须带上第一步返回的访问 Token：

```http
X-Auth-Token: <第一步返回的访问Token>
Content-Type: application/json
```

### 3.3 路径参数

- `dsId`：目标数据集 ID

注意：

- 这个接口获取的是“数据集数据”，不是“卡片数据”
- 如果后续目标是报表卡片，需要确认该卡片背后的数据集 ID，或者改用“获取卡片数据”接口

### 3.4 请求体示例

最小请求体可先从分页和排序开始：

```json
{
  "offset": 1,
  "limit": 10,
  "sortFactor": {
    "name": "id",
    "sortType": "desc"
  }
}
```

字段说明：

- `offset`：偏移位置
- `limit`：返回条数，文档说明单次最多 5 万行
- `sortFactor.name`：排序字段名
- `sortFactor.sortType`：排序方向，常见值为 `asc` 或 `desc`

### 3.5 curl 示例

```bash
curl --location 'https://bi.leyopharm.com/public-api/data-source/<dsId>/data' \
  --header 'X-Auth-Token: <第一步返回的访问Token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "offset": 1,
    "limit": 10,
    "sortFactor": {
      "name": "id",
      "sortType": "desc"
    }
  }'
```

### 3.6 成功响应示例

```json
{
  "result": "ok",
  "response": {
    "dsId": "<dsId>",
    "name": "<数据集名称>",
    "rowCount": 100,
    "colCount": 4,
    "columns": [],
    "preview": []
  }
}
```

返回结果中通常会包含：

- 数据集基础信息
- 字段列表 `columns`
- 预览数据 `preview`

## 4. 两步串联说明

整体调用顺序如下：

1. 使用应用 Token 和 `loginId` 调用登录接口
2. 从登录响应中取出 `response.token`
3. 将该值放入第二步请求头 `X-Auth-Token`
4. 携带 `dsId` 调用数据集数据接口

伪代码示例：

```text
step1_response = POST /public-api/user/loginId/sign-in
access_token = step1_response.response.token

step2_response = POST /public-api/data-source/{dsId}/data
headers["X-Auth-Token"] = access_token
```

## 5. skill 落地建议

如果要放进 `guandata-api-skill`，建议拆成两个动作：

### `login_by_login_id`

输入：

```json
{
  "baseUrl": "https://bi.leyopharm.com",
  "appToken": "<应用Token>",
  "loginId": "<用户loginId>"
}
```

输出：

```json
{
  "success": true,
  "accessToken": "<访问Token>",
  "expireAt": "2026-04-13 18:00:00.000"
}
```

### `get_dataset_data`

输入：

```json
{
  "baseUrl": "https://bi.leyopharm.com",
  "accessToken": "<访问Token>",
  "dsId": "<数据集ID>",
  "body": {
    "offset": 1,
    "limit": 10
  }
}
```

输出：

```json
{
  "success": true,
  "data": {
    "result": "ok",
    "response": {}
  }
}
```

## 6. 当前待补充项

要真正调通第二步，还需要补齐以下信息：

- 正确可用的应用 Token
- 正确可用的 `loginId`
- 目标数据集 `dsId`

如果后续目标不是数据集，而是“20 厂牌进度报表的某个卡片”，还需要进一步确认：

- 卡片 ID
- 页面 ID
- 卡片对应的数据集 ID
- 是否应改用“获取卡片数据”接口，而不是数据集接口
