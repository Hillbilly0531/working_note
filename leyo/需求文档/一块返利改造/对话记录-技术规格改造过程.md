现在来定每一份文档的内部结构。我提供 **3 种组织方式**：

| | **A: 按层次组织** | **B: 按场景组织** | **C: 混合式** |
|---|---|---|---|
| **思路** | 数据模型→API→交互→计算，逐层展开 | 按采购金额/采购数量/销售数量各一章节，每章含完整前后端 | 概述+数据模型是公共章，后面按场景各自展开 |
| **优点** | 找模型看模型、找API看API，结构清晰 | 每个场景自包含，适合分任务开发 | 兼顾复用和场景独立性 |
| **缺点** | 场景逻辑分散在不同层次 | 数据模型/通用API会重复 | 文档稍长 |
| **推荐** | ✅ 推荐 | | |

**推荐 A**，理由：
- 两块实际改动有大量共用部分（计退规则、返利规则、每满X件），按层次组织避免重复
- API 和数据模型天然是跨场景共享的
- 开发时按职责分工：前端看交互→找API，后端看模型→找计算逻辑
