# 一块返利改造 - 前端接口对接文档

## 1. 对接范围

本次改造复用现有普通返利协议接口，在协议主信息、总体限制阶梯、商品限制阶梯中新增字段。

接口统一前缀：

```text
/web/rebateInput
```

响应仍沿用现有 `JsonResultAdapter` 包装结构，本文只描述 `data` 内与本次改造相关的字段。

版本号待后端确认，当前建议使用新版本 `pv2980`；如后端最终复用既有版本，以联调环境实际路径为准。

## 2. 新增字段

### 2.1 协议主信息字段

| 字段 | 类型 | 取值 | 说明 |
| --- | --- | --- | --- |
| `returnRule` | `Integer` | `0` 不计退，`1` 计退 | 计退规则，仅一块医药适用。 |
| `rebateRule` | `Integer` | `0` 每 1 件返利，`1` 每满 X 件返利 | 返利规则，采购数量、销售数量普通型适用。 |

### 2.2 阶梯字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `perX` | `Integer` | 每满 X 件，`rebateRule=1` 时必填且大于 0。 |
| `rebateAmount` | `BigDecimal` | 每满 X 件返利金额，`rebateRule=1` 时必填且大于 0，最多 2 位小数。 |

字段位置：

- 总体限制：`limitList[].perX`、`limitList[].rebateAmount`
- 商品限制阶梯：`goodsdocList[].billList[].perX`、`goodsdocList[].billList[].rebateAmount`

## 3. 展示和入参规则

> [!warning]
> **所有保存类接口统一执行同一套阶梯互斥校验**（包括但不限于：`addRebateIntact`、`updateRabateLimit`，以及后续可能扩展的保存接口）：
>
> - `rebateRule=0`（每1件返利）时：只允许传 `rebatePrice`，禁止传 `perX`、`rebateAmount`
> - `rebateRule=1`（每满X件返利）时：只允许传 `perX`、`rebateAmount`，禁止传 `rebatePrice`
>
> 后端不会静默清空冲突字段，携带冲突字段将直接校验失败。

### 3.1 适用方规则

| 场景 | `returnRule` | `rebateRule` |
| --- | --- | --- |
| 一块医药 + 按采购金额普通型 | 可选，默认 `0` | 不适用，前端不要传。 |
| 一块医药 + 按采购数量普通型 | 可选，默认 `0` | 可选，默认 `0`。 |
| 一块医药 + 按销售数量普通型 | 固定 `0`，不可编辑 | 可选，默认 `0`。 |
| 非一块 + 按采购数量普通型 | 不适用，前端不要传 | 可选，默认 `0`。 |
| 非一块 + 按销售数量普通型 | 不适用，前端不要传 | 可选，默认 `0`。 |
| 非一块 + 按采购金额普通型 | 不适用，前端不要传 | 不适用，前端不要传。 |

说明：

- 一块医药由后端按供应商 `providerType=3` 识别，前端不需要额外传识别字段。
- 非一块场景传 `returnRule` 会被后端拒绝。
- 采购金额场景传 `rebateRule` 会被后端拒绝。

### 3.2 阶梯互斥规则

| `rebateRule` | 前端展示 | 必填字段 | 禁传字段 |
| --- | --- | --- | --- |
| `0` 每 1 件返利 | 展示原“返利单价” | `rebatePrice` | `perX`、`rebateAmount` |
| `1` 每满 X 件返利 | 展示“每满 X 件”“返利金额” | `perX`、`rebateAmount` | `rebatePrice` |
| `null` | 金额型原逻辑 | 沿用原金额阶梯字段 | `perX`、`rebateAmount` |

后端不会静默清空冲突字段。前端切换规则时，应主动清空另一组字段，避免保存失败。

## 4. 接口清单

### 4.1 保存完整返利协议

```text
POST /web/rebateInput/addRebateIntact/{version}
```

用途：新增完整普通返利协议。本次新增字段随现有 `RebateIntactSaveRequest` 提交。

请求体关键字段：

```json
{
  "ysbProviderId": "1001",
  "rebateType": 0,
  "rebateMethod": 2,
  "returnRule": 1,
  "rebateRule": 1,
  "limitList": [
    {
      "lowerNum": 1,
      "upperNum": 10,
      "perX": 5,
      "rebateAmount": 1.00
    }
  ],
  "goodsdocList": [
    {
      "goodsId": "123",
      "billList": [
        {
          "lowerNum": 1,
          "upperNum": 10,
          "perX": 5,
          "rebateAmount": 1.00
        }
      ]
    }
  ]
}
```

返回：

```json
{
  "data": 12345
}
```

### 4.2 保存总体限制

> [!warning]
> 该接口保存前会按协议主表 `rebateRule` 做阶梯字段互斥校验，`limitList` 里禁止混传两套字段：
>
> - `rebateRule=0`：`limitList[].rebatePrice` 必填，`limitList[].perX`、`limitList[].rebateAmount` 禁传
> - `rebateRule=1`：`limitList[].perX`、`limitList[].rebateAmount` 必填，`limitList[].rebatePrice` 禁传

```text
POST /web/rebateInput/updateRabateLimit/{version}
```

用途：单独保存返利协议汇总限制。后端会按协议主表 `rebateRule` 校验阶梯字段。

请求体关键字段：

```json
{
  "rebateId": 12345,
  "ysbProviderId": "1001",
  "rebateType": 0,
  "limitList": [
    {
      "lowerNum": 1,
      "upperNum": 10,
      "perX": 5,
      "rebateAmount": 1.00
    }
  ]
}
```

返回：

```json
{
  "data": true
}
```

错误示例（会失败）：

```json
{
  "rebateId": 12345,
  "limitList": [
    {
      "lowerNum": 1,
      "upperNum": 10,
      "rebatePrice": 0.50,
      "perX": 5,
      "rebateAmount": 1.00
    }
  ]
}
```

说明：同一阶梯对象内混传 `rebatePrice` 与 `perX/rebateAmount`，会触发互斥校验失败。

### 4.3 查询总体限制

```text
POST /web/rebateInput/queryRabateLimit/{version}
```

请求体：

```json
{
  "rebateId": 12345,
  "ysbProviderId": "1001"
}
```

返回 `data` 中每个阶梯会新增：

```json
[
  {
    "lowerNum": 1,
    "upperNum": 10,
    "rebatePrice": null,
    "perX": 5,
    "rebateAmount": 1.00
  }
]
```

### 4.4 查询完整协议详情

```text
POST /web/rebateInput/getRebateIntactById/{version}
```

用途：新增、修改、查看详情页回显。

请求体：

```json
{
  "rebateId": "12345",
  "ysbProviderId": "1001"
}
```

返回关键字段：

```json
{
  "data": {
    "id": "12345",
    "rebateType": 0,
    "rebateMethod": 2,
    "returnRule": 1,
    "rebateRule": 1,
    "limitList": [
      {
        "lowerNum": 1,
        "upperNum": 10,
        "rebatePrice": null,
        "perX": 5,
        "rebateAmount": 1.00
      }
    ],
    "goodsdocList": [
      {
        "goodsId": "123",
        "billList": [
          {
            "lowerNum": 1,
            "upperNum": 10,
            "rebatePrice": null,
            "perX": 5,
            "rebateAmount": 1.00
          }
        ]
      }
    ]
  }
}
```

历史数据兼容：

- 一块采购金额、采购数量历史空 `returnRule`：详情按 `0` 返回。
- 一块销售数量历史空 `returnRule`：详情按 `0` 返回。
- 非一块历史空 `returnRule`：详情返回 `null`。
- 采购数量、销售数量历史空 `rebateRule`：详情按 `0` 返回。
- `rebateRule=0` 时，`perX/rebateAmount` 不应回显有效值。

### 4.5 根据返利编号查询详情

```text
POST /web/rebateInput/getRebateIntactByCode/{version}
```

用途：按返利协议编号查询完整详情。返回字段规则同 `getRebateIntactById`。

请求体关键字段：

```json
{
  "rebateCode": "FL202604300001",
  "ysbProviderId": "1001"
}
```

### 4.6 查询历史详情

```text
POST /web/rebateInput/queryRebateHistoryDetail/{version}
```

用途：有效协议历史版本详情。

请求体：

```json
{
  "id": 12345
}
```

返回字段规则同 `getRebateIntactById`。历史空值只在响应层补默认值，不会回写历史数据。

### 4.7 查询审批详情

```text
POST /web/rebateInput/getAuditRebateIntactById/{version}
POST /web/rebateInput/getLastVersionAuditRebateIntactById/{version}
```

用途：审批详情对比当前版本和上一版本。

请求体：

```json
{
  "rebateId": "12345",
  "ysbProviderId": "1001"
}
```

返回中本次新增字段出现位置：

- 主信息：`data.returnRule`、`data.rebateRule`
- 对比主信息：`data.rebateResponse.returnRule`、`data.rebateResponse.rebateRule`
- 总体限制对比：`data.rebateLimitAuditListResponse` 内的限制阶梯对象
- 商品限制对比：`data.goodsDocList[].billList[]` 内的商品阶梯对象

前端审批对比页需要支持以下字段差异展示：

- 计退规则：`returnRule`
- 返利规则：`rebateRule`
- 每满 X 件：`perX`
- 每满 X 件返利金额：`rebateAmount`
