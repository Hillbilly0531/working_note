## 1. 需求关键要素

来源文档：

- `docs/v29.8.0一块返利改造/页面部分-pms-rebate-原始文档.md`
- `docs/v29.8.0一块返利改造/页面部分-pms-rebate-技术规格.md`

### 1.1 新增字段

- `returnRule`：计退规则，仅一块医药适用。
- `rebateRule`：返利规则，采购数量、销售数量普通型适用，一块和非一块均适用。
- `perX`：每满 X 件，`rebateRule=PER_X_ITEMS` 时必填。
- `rebateAmount`：每满 X 件返利金额，`rebateRule=PER_X_ITEMS` 时必填。

### 1.2 新增枚举

- `ReturnRule`
  - `NO_RETURN_DEDUCTION`：不计退。
  - `WITH_RETURN_DEDUCTION`：计退。
- `RebateRule`
  - `PER_ITEM`：每 1 件返利。
  - `PER_X_ITEMS`：每满 X 件返利。

建议 Java 和 DB 层采用 `Integer code`：

- `return_rule`：`0-不计退`，`1-计退`。
- `rebate_rule`：`0-每1件返利`，`1-每满X件返利`。

如果前端坚持字符串枚举，建议只在 DTO/适配层转换，落库仍保持整数，贴合当前项目枚举风格。

### 1.3 业务决策点

- 一块医药识别：当前 `ProviderAuthPO.providerType` 已定义 `3-一块医药`，可作为适用方判断依据。
- 按采购金额普通型：仅新增 `returnRule`，`rebateRule` 不适用。
- 按采购数量普通型：新增 `returnRule` 和 `rebateRule`。
- 按销售数量普通型：一块 `returnRule` 固定为不计退且不可更改；非一块 `returnRule` 为空；`rebateRule` 可配置。
- 非一块：`returnRule` 必须为空；采购数量、销售数量仍支持 `rebateRule`。

### 1.4 阶梯互斥规则

- `rebateRule=PER_ITEM`：`rebatePrice` 必填，`perX/rebateAmount` 必须为空。
- `rebateRule=PER_X_ITEMS`：`rebatePrice` 必须为空，`perX/rebateAmount` 必填。
- `rebateRule=null`：采购金额场景，沿用原有金额阶梯字段。

### 1.5 公式

每满 X 件返利：

```text
返利金额 = ROUNDDOWN(数量 / perX) * rebateAmount
```

计退规则：

- 不计退：计算阶梯、返利时不扣减采退/销退数据。
- 计退：计算阶梯、返利时扣减采退/销退数据。

说明：当前仓库是 PMS 协议配置与展示侧，真实计算更可能落在 `lunar-rebate-service`。本仓任务先保证配置可保存、可回显、可进入审批/历史/快照链路。

### 2.3 DDL 评审点

- 不建议在 DB 层设置默认值，历史兼容放在代码归一化里处理。
- 暂不建议加索引，除非后续页面需要按 `return_rule/rebate_rule` 筛选。
- `return_rule/rebate_rule` 必须同时覆盖主表、日志表、快照表。
- `per_x/rebate_amount` 必须同时覆盖总体限制表、商品阶梯表、日志表、快照表。
